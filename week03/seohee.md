# 4장_자바가 확장한 객체지향
## 01_abstract 키워드-추상 메서드와 추상 클래스
추상메서드: 선언부는 있는데 구현부가 없는 메서드 

`일반 메서드 = 메서드 선언 + 구현 / 추상 메서드= 선언 + 구현은 자식 클래스가 해야함`
```java
abstract class 동물{
  abstract void 울어보세요();
  }

  class 쥐 extends 동물{
  void 울어보세요(){
      System.put.println("찍찍");
      }
  }

  class 고양이 extends 동물{
  void 울어보세요(){
      System.put.println("야옹");
      }
  }

  public class Driver{
    public static void main(String[] args){
      동물[] 동물들 = new 동물[2];

      동물들[0] = new 쥐();
      동물들[1] = new 고양이();

      for(int i = 0; i < 동물들.length; i++){
        동물들[i]. 울어보세요();
       }
     }
  }
```
```java
class 동물 {
  void 울어보세요(){
  }
}
```
동물들[0].울어보세요()를 호출하는데 여기서 동물들[0]의 참조변수 타입이 동물이므로 자바 입장에서는 동물 클래스에 울어보세요()는 메서드가 존재해야 함.
따라서 최소한 다음과 같은 메서드가 있어야 한다.
```java
class 동물 {
	void 울어보세요(){
	}
}

class 쥐 extends 동물 {
}
```
- 추상 메서드를 쓰는 이유
1. 자식 클래스가 울어보세요()를 반드시 구현하게 강제할 수 있다.
빈 메서드로 두면 부모의 빈 메서드를 물려받으므로 컴파일 오류가 안 난다. 따라서 개발자가 쥐의 울음소리 구현을 깜빡해도 알 수 없다.	
2. 빈 메서드 방식이면 `동물 a = new 동물();`  도 가능하다. 그런데 추상 클래스로 만들면 오류가 된다. 즉 동물 자체를 객체로 만드는 것도 막아준다.
   
**정리) 기본 동작은 아무것도 안 하는 것으로 하고 자식이 바꾸지 않아도 된다면 { }를 비우고 추상화는 여기서 동작을 정할 수 없고 자식 클래스가 반드시 직접 만들어야 할 때 쓸 수 있다.**

 ## 02_생성자
 `동물 뽀로로 = new 동물();`
 
 생성자 = 객체 생성자 메서드 : 반환값이 없고 클래스명과 같은 이름을 가진 메서드
 
 ```java
public class 동물{
     //public 동물() {}
  }
```
동물 클래스에는 아무런 메서드도 없는 것처럼 보이지만 아무런 인자도 갖지 않는 기본 생성자 메서드가 존재한다.
컴파일 과정에서 자바 컴파일러가 알아서 만들어준다.
```java
new 동물("뽀로로"); // 가능: String 인자를 받는 생성자가 있음
new 동물();         // 오류: 인자 없는 생성자가 없음
```
자바의 특징: 인자가 있는 생성자를 하나라도 만들면 자바는 기본 생성자를 만들어 주지 않는다.

```java
class 동물{
  동물(){
      ````
  }
  동물(String 이름){
      ````
  }
}
```
-> 직접 두 생성자 만들어야함.

## 07_interface 키워드와 implements 키워드
interface는 public 추상 메서드와 public 정적 상수만 가질 수 있다. 
```java
interface Speakable{
	double PI = 3.14;
	void say();
```

따라서 메서드에 public과 abstract, 속성에 public과 static, final을 붙이지 않아도 자바가 자동으로 알아서 붙여준다.

```java
interface Speakable{
	public static final double PI = 3.14;
	public abstract void say();
```
## 08_this 키워드
- 지역변수와 속성(객체 변수, 정적 변수)의 이름이 같은 경우 지역 변수가 우선한다.
```java
  class 펭귄 {
    int 나이 = 5; // 객체 변수

    void 소개() {
        int 나이 = 2; // 지역 변수

        System.out.println(나이);      // 2: 지역 변수
        System.out.println(this.나이); // 5: 이 객체의 필드
    }
}
```
나이라고 쓰면 가까운 곳에 선언된 지역 변수 2를 사용하고 객체 변수 나이를 사용하고 싶으면 this.나이라고 써야한다.
- 정적 변수와 이름이 같은 지역 변수가 있는 경우 정적 변수를 사용하려면 클래스명을 접두사로 사용한다.

## 09_super 키워드
바로 위 상위 클래스의 인스턴스를 지칭함.
```java
class 동물{
	int var = 10;
}

class 펭귄 extends 동물{
	void test(){
		System.out.println(super.var);
	}
}
```
super 키워드로 상위 클래스의 인스턴스 메서드를 호출하므로 동물에 있는 10이 출력된다.

# 5장_객체 지향 설계 5원칙-SOLID
## 01_SRP(Single Responsibility Principle)-단일 책임 원칙
:클래스를 역할에 따라서 분할하는 것을 말한다. 
- 클래스뿐만 아니라 속성, 메서드, 패키지, 모듈, 컴포넌트, 프레임워크 등에도 적용 가능하다.
- 객체 지향 4대 특성 중 추상화와 관련이 있다. 공통적이고 핵심적인 개념을 뽑아내는 것이 추상화이기 때문이다.
```java
void 행동하다(){
	if(this.사람 = 학생){
		//공부한다.
	}else{
		//가르친다.
```
행동하다() 메서드에서 학생이냐 교수님이냐 따라서 분기 처리가 진행되고 있음을 볼 수 있다. 
행동하다() 메서드가 교수님과 학생 모두를 구현하려고 하기에 단일 책임 원칙을 위배라고 있는 것이다.
다음과 같이 코드를 바꿀 수 있다.
```java
class 교수님 extends 사람{
	void 행동한다(){
		//가르친다.
	}
}
class 학생 extends 사람{
....
```
## 02_OCP(OPen Closed Principle) 개방 폐쇄 원칙
:새로운 기능을 추가할 수 있도록 열어 두되 기존 코드는 되도록 수정하지 않도록 설계하는 원칙

자바에 적용되어 있는 사례:

- JVM: 개발자는 자바 코드를 작성하고 .class 파일로 컴파일한다. 운영체제마다 해당 환경에서 실행되는 JVM이 있어, 같은 자바 프로그램을 여러 운영체제에서 실행할 수 있다.
  
- 상속·인터페이스: 기존 기능의 공통 규칙을 유지하면서 새로운 하위 클래스나 구현 클래스를 추가할 수 있다. 

- 유연성, 재사용성, 유지보수성을 얻을 수 있다.

## 03_LSP(Liskov Substitution Principle) 리스코브 치환 법칙
- 하위 분류는 상위 분류의 한 종류다.
- 하위에 존재하는 것들은 상위에 있는 것들의 역할을 하는 데 전혀 문제가 없어야한다.
```java
class 새 {
    void 날기() { System.out.println("날아간다"); }
}

class 참새 extends 새 { }

class 펭귄 extends 새 {
    @Override
    void 날기() { throw new UnsupportedOperationException(); }
}

```
새 객체를 받아서 날기()를 호출한다고 했을 때 참새를 받으면 날아가지만 펭귄을 넣으면 오류가 된다.
즉, 새의 하위 클래스라고 선언해 놓고 새의 역할을 대신할 수 없으므로 LSP를 위반하는 것이다.


## 04_ISP(Interface Segregation Principle) 인터페이스 분리 원칙
- 클래스의 역할을 인터페이스 제한을 통해서 나누는 것이다.
- 상위클래스에는 하위 클래스들이 공통으로 사용하는 기능을 충분히 담고 
 인터페이스에는 꼭 필요한 기능만 담는 것이 좋다.

## 05_DIP(Dependency Inversion Principle) 의존 역전 원칙

자주 바뀌는 클래스에 직접 의존하지 않고 그 클래스들이 공통으로 따르는 인터페이스의 의존하도록 만드는 것. 실제 클래스를 바꿔도 이를 사용하는 코드는 수정할 필요가 줄어든다.
```java
자동차 - 스노우 타이어
자동차 -       타이어
         /      ㅣ         \
스노우 타이어  일반 타이어  광폭 타이어

```
자주 변경되는 스노우 타이어에 의존하지 않고 추상화된 타이어 인터페이스에만 의존하게 함으로써 타이어가 변경되어도 자동차는 영향을 받지 않음.


## 정리
**SoC**: 관심이 같은 것끼리는 하나의 객체 안으로 또는 친한 객체로 모으고 관심이 다른 것은 가능한 따로 떨어져 영향을 주지 않도록 분리하는 것. 
하나의 속성, 메서드, 클래스, 모듈, 패키지에는 하나의 관심사만 들어 있어야한다.
- 스프링은 Soc를 통해 SOLID를 적용하고 있다.
