1장. 사람을 사랑한 기술 ~ 2장. 자바와 절차적/구조적 프로그래밍



## 학습 내용

### 1. 객체지향 프로그래밍 언어의 등장 배경

#### 기계어와 어셈블리어

- 기계어: 0과 1로만 표현된 기계가 이해하는 유일한 언어.
- 어셈블리어: 기계어를 일상 용어로 표현한 프로그래밍 언어. 어셈블리어를 기계어로 번역해주는 소프트웨어 어셈블러 필요.
- 기계어와 어셈블리어는 CPU에 따라 다르며, 어셈블러 또한 상호 호환되지 않았음.
- 같은 작업을 하는 프로그램의 소스 파일을 실행 기종만큼 만들었어야 함.

#### C언어

- One Source Multi Object Use Anywhere

- 같은 작업을 하는 프로그램의 소스 파일을 하나만 만들면 됨.(One Source)
- 소스 파일을 OS별로 다른 컴파일러로 컴파일하여 목적 파일 생성.(Multi Object)
- 운영체제별 소스 수정 과정이 필요함.

#### 자바

- 진정한 객체지향 언어.
- Write Once Use Anywhere
- 단일 컴파일러, 단일 목적 파일만 필요로 함.(단, 컴퓨터별로 해당 기종용 JRE 설치 필요) 

### 2. 자바 프로그램 개발과 구동

JDK 에서 개발된 프로그램은 JRE에 의해 가상 컴퓨터 JVM 상에서 구동.

이러한 구조는 기존에 각 플랫폼별로 별도의 설치파일을 준비해야 했던 불편함을 없애기 위함.

#### JDK

- Java Development Kit. 자바 개발 도구.

- 자바 소스 컴파일러(javac) + JRE

#### JRE

- Java Runtime Environment. 자바 실행 환경.
- 플랫폼별 JRE를 별도로 설치 필요.
- 자바 실행기 + JVM

#### JVM

- Java Virtual Machine. 자바 가상 기계
- 자바 프로그램은 이 위에서 동작함.

### 3. T 메모리 구조

프로그램이 실행될 때, 객체지향 프로그램이 메모리를 사용하는 방식을 단순화한 구조.

메모리는 크게 코드 실행 영역, 데이터 저장 영역으로 구분됨.
데이터 저장 영역은 다시 스태틱 영역, 스택 영역, 힙 영역으로 구분됨.

### 4. main() 메서드

프로그램의 시작점이자 끝

```java
public class Sample {
	public static void main(String[] args) {
    int score = 90;
    
    if (score >= 90) {
			String applause = "참 잘했어요!";
      System.out.println(applause + " 점수: " + score);
    }
  }
}
```

위 코드를 실행하면 T메모리 구조는 다음과 같음.

1. JRE가 프로그램 안에 `main()` 메서드 있는지 확인 -> JVM 부팅 및 목적 파일 실행.
2. **JVM 전처리**: `java.lang` 패키지 및 개발자가 작성한 모든 클래스와 임포트 패키지를 스태틱 영역에 배치.
3. `main()` 메서드 스택 프레임을 스택 영역에 할당.
4. 메서드 인자 `args` 변수 공간을 `main()` 스택 프레임 내에 확보.
5. 스택 프레임 내에 4바이트 정수 `score` 변수 공간 마련하고, 값 90 할당.
6. if 구문이 true 이므로, `main()` 스택 프레임 내에 `if(true)` 스택 프레임 마련.
7. `if(true)` 스택 프레임 내에 `applause`  문자열 변수 공간 마련하고, 값 "참 잘했어요!" 할당.
8. 콘솔에 `System.out.println` 내용 출력. 종료되면 `if(true)` 스택 프레임 소멸.
9. `main()` 메서드가 끝나 스택 프레임 소멸.
10. JVM 종료.

### 5. 변수

변수는 메모리 내 모든 영역에 존재할 수 있다. 그러나, 각각의 영역에 있는 변수는 서로 다른 목적을 갖는다.

#### 지역 변수

- 스택 영역 내 스택 프레임 안에서 존재. 스택 프레임이 사라지면 함께 사라짐.
- **외부 스택 프레임에서 내부 스택 프레임의 변수에 접근하는 것은 불가능하지만, 그 역은 가능하다.**

#### 클래스(스태틱) 멤버 변수

- 스태틱 영역 안에서 존재. JVM이 종료될 때까지 고정된 상태로 존재.
- 전역변수로서 **코드 어디서나 접근이 가능**하기 때문에, 이 값을 여러 곳에서 변경하기 시작하면 전역변수에 저장된 값을 파악하기 쉽지 않으므로 **사용을 권장하지 않음**.
- 다만 **전역 상수**로 사용할 때는 사용 권장.(`static final`)

#### 객체 멤버 변수

- 힙 영역 안에서 존재. 변수가 소속된 객체와 함께 가비지 컬렉터에 의해 소멸.

### 6. Call by Value

메서드를 호출할 때 인자로 변수가 저장한 값만 복사해서 전달하는 방식.

```java
class Sample {
	public static void main(String[] args) {
    int a = 3;
    
    System.out.println("update(a) = " + update(a));
    System.out.println("a = " + a);
  }
  
  private static int update(int a) {
    a = a + 5;
    return a;
  }
}
```

위 코드에서 콘솔 출력 결과는 다음과 같다.

```bash
update(a) = 8
a = 3
```

`update(a)`를 거쳐도 `main()`의 `a`가 8로 바뀌지 않는 이유는, 호출 시 변수 `a`의 **값을 복사해서** 인자로 넘긴 것이지 변수 `a` 자체를 넘긴 것이 아니기 때문. `main()`의 `a`와 `update()`의 `a`는 서로 다른 스택 프레임에 있는 별개의 변수임.

### 7. 멀티 스레드

- T 메모리의 스택 영역을 스레드 개수만큼 분할해서 쓰는 방식.
- 하나의 스레드에서 다른 스레드 스택 영역에는 접근 불가하지만, 스태틱/힙 영역은 공유하는 구조.
- 멀티 프로세스 대비 메모리를 적게 사용.

### 8. 멀티 프로세스

- 다수의 T 메모리를 갖는 구조. 메모리 사용량이 많음.
- 프로세스마다 각자의 T 메모리를 갖고, 이는 각자 고유의 공간이므로 서로 참조 불가.
- 즉, 프로세스간 메모리 영역 침범이 불가하여 메모리 안정성이 높지만 메모리 사용량이 높음.
